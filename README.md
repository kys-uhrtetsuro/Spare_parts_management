# 予備品管理システム

React + Django + SQLite + pywebview + Nuitka によるWindows用ローカル在庫管理。

## 機能

- システムマスタ（同一SQLiteに複数システム、親拠点や住所のDB管理は不要）
- 品番・型式・品名の複合マスタとオートコンプリート、未登録品の明示登録
- 補充/使用の履歴蓄積で現在庫を集計、マイナス在庫は禁止。登録者名を保持し、企業名の入力は不要
- 履歴訂正は取消逆仕訳＋新規履歴の追記（元履歴は変更せず保持）
- 品番/型式/両方の変更は後継品を新規レコードとして作成し旧品と連結する。旧品番の在庫・履歴は旧品番のまま維持し、在庫は自動移動しない
- 機器マスタ（正式名・通称）はシステム配下、各機器には任意の複数部位。分類は共通マスタ。部品は共通で、機器・部位割当はシステム×部品単位で管理
- Django Adminの選択画面を参考にした下限設定2列UI、設定値1以上、複数件一括保存
- 現在庫1以上もしくは下限設定ありをExcelで出力（設定済み0個も出力）
- 下限在庫一覧：下限以下の部品をシステム・機器・部位・分類別に確認。補充が必要な数量の差分を表示
- 下限在庫の常時表示警告：アプリ上部から一覧へ移動。Windowsではデスクトップ通知（アプリ起動中・ON/OFF可）
- DBバックアップ作成

## 必要環境

- 開発: Python 3.12、Node.js 24、npm
- 利用者: Windows 10/11、Microsoft Edge WebView2 Runtime。Python、Node.js、DBサーバーは不要
- SQLiteのファイルはEXEと別に保存。配布先のフォルダに書込権限が必要

Windows PowerShell:

~~~powershell

~~~

## Windows EXE作成

Windows配布は **Nuitka standalone方式のみ**です。依存ファイルを `src/` に集約し、ルートにはC製の小さな起動ランチャーを配置します。PyInstallerは使用しません。

~~~powershell
./scripts/build_windows.ps1
~~~

ビルドにはWindows 64bit、Python 3.12、Node.js 24、MSVC（Visual Studio C++ Build Tools）が必要です。

~~~text
SparePartsManagement-package/
├─ SparePartsManagement.exe       # 利用者が起動
└─ src/
   ├─ SparePartsManagement.exe    # Nuitka本体
   ├─ *.dll / *.pyd
   ├─ django/
   ├─ frontend/
   └─ assets/
~~~

ビルドは `build/SparePartsManagement-package/` を生成します。GitHub Actionsでは `releases/SparePartsManagement-standalone.zip` へまとめ、Git制限超過時はGitHub Releasesの添付ファイルとして配布します。
Djangoの日本語翻訳リソースも同梱します。毎回の一時展開はありません。
利用者PCにPythonやNode.jsは不要ですが、Microsoft Edge WebView2 Runtimeは必要です。

## 配布・バックアップ

ZIPを**全展開**し、外側の `SparePartsManagement.exe` を起動してください。`src/` のEXEやDLLだけ取り出してはいけません。

~~~text
SparePartsManagement/
├─ SparePartsManagement.exe
├─ src/                       # 本体と依存ファイル
└─ data/                      # 初回起動時に生成、以後維持
   ├─ inventory.sqlite3
   ├─ startup.log
   └─ backups/
~~~

初回起動で外側のEXEと同じディレクトリに `data/inventory.sqlite3` が作られ、マイグレーションが実行されます。既存DB・履歴・SQLite内の秘密鍵はそのまま維持します。
`data/` にはログ・単一起動ロック・バックアップも配置します。更新時は **dataフォルダを削除・上書きせず**、EXEとsrcを入れ替えてください。
復元時はアプリを終了し、バックアップを `data/inventory.sqlite3` にコピーします。配布先フォルダの書込権限が必要です。
ネットワーク共有上のSQLite運用や同一dataフォルダでの同時起動は避けてください。

## Excelによるシステム別フォーク（取り込み・書き出し）

1. 現在庫一覧で対象システムを選ぶ（「すべて」なら複数システムを出力）。
2. 「Excel出力」を押し、Windowsの「名前を付けて保存」で保存先とファイル名を指定する（既定のファイル名は `spare_parts_stock.xlsx`）。ブラウザでアクセスした場合は通常のダウンロードを使用する。
3. コピー先のアプリで「Excel取込」→xlsx選択→プレビュー→確定。
4. 同名システムがある場合、単一システムのExcelなら別の移植先名称を指定できる。

「現在庫」シートの**現在庫（0以上）と下限値（空欄または1以上）**のみ編集可能。
行の削除・品番や品名の改変・非表示シートの削除は取り込みエラーとなる。
非表示シートには使用された部品、品番・型式の新旧対応、機器・部位・分類、
システム、在庫・下限のスナップショットを含める。履歴に登場して在庫0となった
部品も非表示シート側に残す。

**移植後の在庫は期首補充として記録**し、元の入出庫イベントそのものは移植しない。
元システムのデータも変更しない。同じファイルの再取り込みは禁止。
別の日時に再出力したExcelは別ファイルと判定されるため、移植先の名称を
重複させて安易に複数回取り込まないこと。マスタの品番・型式等が既存DBと矛盾する
場合は、トランザクション全体を取り消す。

DB全体をそのまま復元したい場合は、アプリを終了して`data/inventory.sqlite3`を
ファイルコピーで置き換える。これはExcel移植と異なり、履歴も丸ごと引き継ぐ。

## Windows対応範囲

- 配布用のGitHub Actions Windowsビルドは**64bit用**。Windows 11 64bitを推奨。
- Windows 10 64bitも対象（WebView2 Runtimeが必要、EXE実機での確認を継続）。

## メニュー・並び順

左メニューは【在庫管理】（現在在庫一覧・入出庫履歴・下限アラート設定）と【システム管理】（システム一覧・機器/部位マスタ・部品分類マスタ・部品マスタ）のアコーディオン。前者は初期展開、後者は初期折り畳み。画面切替では開閉状態を維持する。
在庫サマリーは最終入出庫更新日時の新しい順。その他のID順一覧は昇順。

## 入出庫・部品の現行品限定とマスタコピー

入庫登録に使える品番・型式は後継品のない現行レコードのみ。出庫登録では、選択中のシステムに在庫が1以上存在する部品（旧品番・旧型式を含む）のみ表示・選択可能。入庫／出庫のボタンと登録画面は分離し、出庫のマイナス在庫は禁止。部品マスタは「後継登録済みを除外」を初期ONにし、OFF時には旧品の履歴・新旧対応を閲覧できるが、旧品は更新不可。過去の入出庫履歴についての訂正機能は維持する。
部品マスタのコピーは、品番・型式・名称・分類・選択中システムの機器割当を複写して新規作成する（品番と型式の重複は禁止）。コピーと後継登録は別機能で、旧品とのバージョンリンクや在庫はコピーしない。
機器マスタのコピーはコピー先システムを選び、名称・通称・全部位を新規登録する。機器に紐付く部品割当はコピーしない。


## タスクバーアイコン

pywebview 6.2 の `webview.start(icon=<icoパス>)` で、ウィンドウ生成時に
WinForms のネイティブアイコンを設定する。表示後に Win32 メッセージで
アイコンを差し替える従来の方式は使わない。
タスクバーのグループ化には固定の `KYS.SparePartsManagement.Desktop`
（AppUserModelID）を起動時に設定する。

生成された `assets/spare_parts.ico` はEXEへリソース埋め込みするだけでなく、
配布フォルダにも同梱する。アイコン欠落は起動時に検出してエラーにする。
Windowsビルドでは EXE 内に Windows アイコンリソースがあることを検査する。

Windowsに以前のアイコンでタスクバーへピン留めしたショートカットがある場合は、
更新後のEXEで起動してから古いピン留めを解除して再登録する
（Windowsのショートカット／アイコンキャッシュはアプリ側では強制更新できない）。


## 後継品の下限アラート自動整理

- 新たに監視対象へ追加できる部品は**後継のない現行品**のみ。
- 後継登録済みで、以前から下限設定が存在する旧品は、旧在庫がある間は監視を継続する。ただしその設定値は変更不可（手動解除は可能）。
- そのシステムで後継品に初めて在庫が入ると、旧品の下限値を後継品へ自動移行し、旧品側を解除する。**後継品に既存の設定がある場合はその値を優先**する。
- 後継品に在庫が入らないまま旧品の在庫が0になった場合、旧品の設定を解除する。後継品への監視設定は勝手に作成しない。
- 品番・型式を何度も更新した場合は、より新しいバージョンまで追跡する。システム間で設定は移動しない。
- 新規の入出庫だけでなく履歴訂正、Excel取り込み、下限設定一括保存、既存DBのマイグレーションでも同じルールを適用する。
- アラートの移行は設定テーブルだけを操作する。在庫履歴・現在庫の値は変更しない。

## 1部品に対する複数機器・部位の割当

共通部品マスタに対し、システムごとに機器／部位を**複数行**登録できます。
同じ機器でも異なる部位（例：搬送機A／駆動部、搬送機A／検出部）は別の割当です。
機器A／駆動部と機器B／駆動部の併用や、部位未指定の機器登録にも対応します。
同じシステム・部品・機器・部位の**完全重複は拒否**します。

部品編集では選択中システムの割当だけを一括更新し、他システムの割当は維持。
後継部品を作る場合は全システムの全割当を引継ぎますが、在庫・履歴は
従来どおり別レコードのままです。コピー新規登録は選択中システムの
割当をフォームに複写し、元レコードは変更しません。

在庫・部品一覧・入出庫モーダルの機器／部位フィルターは複数割当を逆引き。
Excel移植形式V3は複数割当行を格納し、V2形式の取り込みにも対応します。
既存DBの1件の割当はマイグレーション0007後もそのまま維持します。

## 下限在庫の警告とデスクトップ通知

- 在庫管理の「下限在庫一覧」で、既存の在庫下限判定に該当する部品を確認します。現在庫が下限値と同数の場合も対象です。
- 全システムの未解消件数を画面上部に表示します。「下限在庫一覧を開く」で絞り込みを解除し一覧へ移動します。
- Windows専用のデスクトップ通知は初期ONで、右上の「デスクトップ通知」でOFF/ONを切り替えます。アプリが起動している間、起動時または警告対象が変化したときに通知します。同一警告の画面更新では再通知しません。
- Windows通知がOS側でブロックされても、画面上部の警告は消えません。通常のブラウザでは通知権限が許可されている場合のみブラウザ通知します。

## Excelフォークの取り込み先

単一システムのExcel取り込みでは、取り込み先を選択します。
- **新規システムを作成（フォーク）**：Excel元システムとは別IDで新規作成。既存と同名なら新しい名称を指定してください。
- **既存システム**：在庫の有無を問わず選択可能。既存部品の数量は入庫履歴を追加して加算し、新規部品・機器・部位・割当は必要分だけ作成します。元ExcelのシステムIDは取り込み先IDと無関係です。既存レコードを上書きしません。
- 複数システムを含むExcelは従来どおり一括新規フォークです。

Excel内の非表示メタデータは機器・部位・部品の参照を復元するために必要です。「Excel内の参照先がない」と表示された場合は、移植先DBの設定ではなくExcel内部のメタデータ不整合です。取り込み先の変更だけでは解消しません。

## Excel取り込み操作（簡略版）
1. 「現在在庫一覧」→「Excel取込」を開き、Excelファイルを指定します。
2. 取り込み先を「新規システムを作成」または任意の既存システムから選択します。取り込み先はExcelの解析前から選べます。
3. 「取り込み実行」を押すと検証と登録をまとめて行います。「内容を確認」は不要です。

既存システムへの合算は**品番・型式**で部品を識別し、システム間・Excel間のPKの一致に依存しません。Excel内部の参照情報に不整合がある場合は、その理由を画面に表示して登録を中止します。

## 型式の省略とExcel見出しの表示名
- 部品登録・後継部品登録・Excel取り込みで「型式」は任意。未入力の型式は空文字列として保存します。
- 部品の重複・在庫合算は「品番＋型式」で判定。同じ品番かつ両方型式空欄の場合のみ同一部品として扱います。
- 新しく出力するExcelの非表示メタデータの**列見出し**も「品番」「型式」「品名」など日本語で表示します。内部シート名と保存フォーマットは互換性維持のため変更せず、古い英語見出しのExcelも取り込めます。
- エラーの項目名も日本語に統一し、内部フィールド名は利用者へ表示しません。

## Excel貼り付け時の品番・型式
- Excelの品番・型式が数値セル（例：123、123.0、12.5）で保存されても、取り込み時に文字列として正規化します。非表示の「部品情報」と表示シート「現在庫」に同じ処理を適用します。
- 部品照合は品番＋型式。型式の空欄も引き続き許可します。
- Excelが数値変換によって消した**先頭ゼロや15桁を超える品番の精度は復元できません**。この場合はExcel上で文字列として正しい値を入力してください。非表示情報と表示情報が不一致のものは、誤った部品へ合算しません。
